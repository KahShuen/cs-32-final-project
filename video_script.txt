VIDEO SCRIPT — Meetup Coordination Tool
========================================

[INTRO — explain the problem]

Our project is a meetup coordination tool for college students.
The problem is simple: everyone's busy, scheduling is a pain.
Each person says who they want to meet and when they're free,
and our tool figures out who should meet as a group and when.

For example — Alice wants to meet Bob, Bob wants to meet Charlie,
Charlie wants to meet Alice. David wants to meet Eve, Eve wants to
meet David. Our tool should figure out: Alice, Bob, and Charlie
are all connected, so put them in one group. David and Eve are
their own group.


[SHOW — example_input.json]

Here's our sample input. It's a JSON file with five users.
Each user has a name, a list of people they want to meet,
and their availability as day/time blocks.


[EXPLAIN — meetup.py, the pipeline]

Our script has five functions that run in order:

1. load_users — just reads the JSON file in. No real logic here.

2. build_graph — this takes the user data and turns it into a
   graph. Each person is a node, and "wants to meet" becomes an
   edge. We store it as a dictionary where each key is a person's
   name and the value is the set of people they're connected to.
   We use a dictionary because looking up someone's connections
   is O(1) — you just index by their name. We use sets for the
   connections because we only care about whether an edge exists,
   not duplicates.

3. find_groups — THIS IS THE MAIN COMPUTATION. We use BFS,
   breadth-first search, to find connected components in the
   graph. Pick an unvisited person, explore everyone reachable
   from them — that's one group. Repeat until everyone is
   visited. For our example, starting at Alice: we reach Bob
   through the edge, then Charlie through Bob, then no one new.
   That's Group 1. David is still unvisited, so we start again:
   reach Eve, no one new. That's Group 2. The time complexity
   is O(V + E) — we visit every person and every edge once.

4. find_common_times — THIS IS THE SECOND COMPUTATION. Once we
   know the groups, we need to find when they can all meet. We
   chop each person's availability into 30-minute blocks and
   represent them as sets. Then we intersect everyone's sets —
   only time blocks where ALL members are free survive. This is
   just set intersection, which Python gives us natively.

5. format_output — just prints the results. No logic.

So to summarize: the two computational pieces are find_groups
(graph traversal via BFS) and find_common_times (set intersection
for scheduling). Everything else is just reading data in and
printing results out.
